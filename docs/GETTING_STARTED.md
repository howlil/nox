# Install Nox and complete a learning session

This tutorial uses a **separate test vault**, especially before Community Directory approval. Nox requires Obsidian desktop; mobile is unsupported.

## Prerequisites

- Obsidian desktop compatible with the [manifest](../manifest.json).
- A test vault with a Markdown note.
- Access to one [supported AI provider](PROVIDERS.md). Nox itself includes no AI credits.

## Install

**After Community Directory approval:** Open Obsidian → Settings → Community plugins → Browse, search Nox, select Install, then Enable.

**Before approval:** Download `main.js`, `manifest.json`, and `styles.css` from the official [Nox Releases](https://github.com/howlil/nox/releases). Place these files under your test vault's `.obsidian/plugins/nox/` folder (or its custom configuration directory). Enable the plugin. Do **not** install GitHub's autogenerated source ZIP.

## Configure an agent

Open **Settings → Nox → Agent provider**. Choose an installed, authenticated AGY CLI or Codex CLI, or an eligible ChatGPT plan account with explicit OAuth authorization. If discovery fails, configure the CLI executable path. See [provider setup](PROVIDERS.md). A login does not guarantee plan-based model inference access.

## First note interaction

1. Create a note named `example.md` with a paragraph you want to understand.
2. Open and select that paragraph.
3. Open Nox using its ribbon icon or the **Open sidebar** command.
4. Ask: **Explain this selection in simple terms.**
5. Check that the response uses the expected note context.

## Practice

Choose the **Practice** learning action, request one question, submit an answer, and review the response. Learning evidence is not inferred from a single chat message.

To experiment with an objective-based learning program, enter:

`/plan Learn networking fundamentals | minutes=30 | sessions=3`

Review the proposed curriculum; use `/start-session` and `/next` to work through activities. Planning needs a configured runtime.

## Expected outcome

A working sidebar, provider selection, a contextual response, and an interactive learning action. Test actual provider connectivity on Obsidian desktop; automated CI mocks external providers.
